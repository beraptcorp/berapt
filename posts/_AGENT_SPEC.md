# 비랩트 인사이트 게시글 작성 사양서 (에이전트용)

> 이 문서는 berapt.com `/insights/`에 실릴 게시글을 작성하는 에이전트를 위한 사양입니다.
> 파일명이 `_`로 시작하므로 빌드·사이트에 노출되지 않습니다.
> 이 사양을 지키면 결과물을 손대지 않고 그대로 빌드할 수 있어야 합니다.

---

## 1. 제출물

게시글 1편당 아래를 제출합니다.

| 항목 | 위치 | 필수 |
|------|------|------|
| 게시글 원고 | `posts/{slug}.md` | 필수 |
| 커버 이미지 | `images/posts/{파일명}` | 필수 |
| 본문 이미지 | `images/posts/{파일명}` | 선택 (권장 1~2장) |
| 검수 메모 | 대화/PR 본문 | 필수 — 6장 체크리스트 결과, 확인 못 한 사실, 사용한 이미지의 출처·라이선스 |

- 하나의 Markdown 파일(UTF-8)로 작성합니다. HTML 파일은 만들지 않습니다. HTML은 빌드 스크립트가 생성합니다.
- 초안 단계에서는 파일명을 `_`로 시작합니다(예: `_tcg-market-2027.md`). `_`로 시작하는 파일은 빌드에서 제외됩니다. 사람이 검수한 뒤 `_`를 떼어 공개합니다.

## 2. 파일명(slug)

파일명이 곧 URL입니다. 예를 들어 `posts/tcg-boom-illustrator.md` → `https://www.berapt.com/insights/tcg-boom-illustrator/`가 됩니다.

- 영문 소문자, 숫자, 하이픈(`-`)만 사용합니다. 한글, 공백, 밑줄은 쓰지 않습니다.
- 3~6단어로 주제를 드러냅니다. 예: `kccf-2026-shoulderpick-review`, `ai-era-human-art-goods`
- 기존 파일과 겹치지 않아야 합니다. 공개 후에는 파일명을 바꾸지 않습니다(링크가 깨집니다).

## 3. 프론트매터

파일 맨 위에 아래 형식 그대로 작성합니다. 필드 순서도 이대로 맞춥니다.

```yaml
---
title: "카드 한 장에 2천만 원, TCG 열풍의 진짜 주인공은 '그림'이다"
description: "전 세계가 다시 카드에 빠졌습니다. 글로벌 24조 원을 향해 달리는 TCG 시장, 그리고 카드 한 장 한 장을 작품으로 만드는 일러스트레이터의 이야기를 짚어봅니다."
date: 2026-05-25
author: 비랩트
image: /images/posts/pokemon_cards.jpg
tags:
  - TCG
  - 트레이딩카드
  - 일러스트레이터
  - 숄더픽
---
```

| 필드 | 규칙 |
|------|------|
| `title` | 25~45자. **큰따옴표로 감쌉니다.** 사이트의 `<h1>`, 브라우저 탭, 검색 결과, SNS 미리보기에 그대로 쓰입니다. |
| `description` | 80~150자, 2문장. **큰따옴표로 감쌉니다.** 검색 결과·SNS 미리보기와 목록 카드 요약에 쓰입니다. 본문 첫 문단을 복사하지 말고 글 전체를 요약합니다. |
| `date` | `YYYY-MM-DD`. 따옴표 없이 씁니다. 공개 예정일을 씁니다. 목록 순서와 홈페이지 노출(최신 4편)이 이 값으로 정해집니다. |
| `author` | 항상 `비랩트` |
| `image` | 커버 이미지 경로. `/images/posts/`로 시작하는 절대경로를 씁니다. |
| `tags` | 3~5개. 띄어쓰기 없는 짧은 명사(예: `서브컬처`, `TCG`, `숄더픽`)로 씁니다. **가장 중요한 태그를 앞에 둡니다.** 홈 카드에는 앞의 2개, 목록에는 앞의 3개만 보입니다. |

### 반드시 지킬 것 (지키지 않으면 페이지가 깨짐)

- `title`과 `description` **안에는 큰따옴표(`"`)를 쓰지 않습니다.** 인용은 작은따옴표(`'`)나 『』「」로 합니다. 빌드 스크립트가 이 값을 HTML 속성에 그대로 넣기 때문에, `"`가 들어가면 메타 태그와 이미지 alt가 깨집니다.
- `title`과 `description`에 `<`, `>`, `&`, 역슬래시(`\`)를 쓰지 않습니다.
- 프론트매터 시작과 끝의 `---`는 반드시 파일 첫 줄과 독립된 줄에 둡니다.

## 4. 본문 구조

기존 게시글 5편의 형식을 따릅니다. 참고 원고: `posts/ai-era-human-art-goods.md`, `posts/kccf-2026-shoulderpick-review.md`

```markdown
![커버 이미지 설명](/images/posts/cover.jpg)
*캡션 한 줄*

## 도입 — 현상/질문을 던지는 소제목

(2~3문단)

## 데이터로 본 현황

(2~4문단, 핵심 수치는 **굵게**)

![본문 이미지 설명](/images/posts/body.jpg)
*캡션 한 줄*

## 의미 — 창작자/팬에게 무엇이 달라지는가

(2~3문단)

## 비랩트가 하는 일 — 숄더픽·숄더·OCC와의 연결

(2~3문단)

---

## 참고 자료

- [매체명 — 기사 제목](https://...)
- [매체명 — 기사 제목](https://...)
```

| 항목 | 규칙 |
|------|------|
| 분량 | 본문 공백 제외 1,800~2,500자(기존 글 평균 약 2,100자) |
| 첫 줄 | 커버 이미지를 한 번 더 넣고 바로 아래 줄에 이탤릭 캡션을 답니다(기존 글과 동일). |
| 소제목 | `##` 4~6개, 필요하면 그 아래 `###`. **`#`(H1)은 쓰지 않습니다.** 제목은 프론트매터 `title`로 자동 표시됩니다. 소제목은 문장형으로 씁니다(예: "사람들은 '진짜'를 원한다"). |
| 문단 | 한 문단 2~4문장. 핵심 수치·결론만 `**굵게**` 처리하고, 한 문단에 굵게는 1~2곳까지만 씁니다. |
| 마지막 섹션 | `---` 구분선 뒤 `## 참고 자료` + 목록. 헤딩 이름을 정확히 `참고 자료`로 써야 작은 글씨 출처 스타일이 적용됩니다. |
| 사용 가능 문법 | 기본 Markdown, 표(`| |`), 코드블록, 인용문(`>`), 구분선(`---`). HTML 태그, 각주, 체크박스, 수식은 쓰지 않습니다. |
| 링크 | 본문 링크는 자동으로 새 탭에서 열립니다. 본문 중간 링크는 최소화하고 출처는 참고 자료에 모읍니다. |

## 5. 내용·톤 기준

### 독자와 목적
- 독자: 서브컬처 팬, 일러스트레이터, 업계 관계자, 투자자
- 목적: 업계 흐름을 데이터로 설명하고, 그 흐름 속에서 비랩트 서비스가 왜 필요한지 자연스럽게 연결합니다. 광고문이 아니라 **인사이트 글**이어야 합니다. 비랩트 언급은 마지막 1~2개 섹션에 모읍니다.

### 문체
- '~합니다'체의 존댓말을 씁니다. 1인칭은 '비랩트는', '우리는'만 씁니다.
- 과장된 감탄, 이모지, 반말, 유행어를 쓰지 않습니다.
- 첫 언급 시 브랜드 표기: **비랩트(BeRapt)**, **숄더픽(ShoulderPick)**, **숄더(Shoulder)**, **숄더픽 OCC(Original Collection Card)**. 이후에는 한글 표기만 씁니다.

### 서비스 설명 (이 범위 안에서만 서술)
- **숄더픽**: 서브컬처 이미지·일러스트 오픈 플랫폼. 작가가 그림을 올리면 조회수·관심도(Pick)에 따라 수익이 배분됩니다. '일러스트레이터판 유튜브'
- **숄더**: 유료 구독 기반 작가 응원 커뮤니티. 멤버십 전용 콘텐츠, 월정기 수익. '유튜브 멤버십형 팬커뮤니티'
- **숄더픽 OCC**: 작가 일러스트로 만든 오리지널 수집 카드. 시즌 1·2 품절, 시즌 3·4 판매 중 (작성 시점에 홈페이지 `index.html`의 OCC 섹션으로 다시 확인)
- 출시되지 않은 기능, 매출, 회원 수, 파트너십은 **사람이 제공한 자료가 있을 때만** 씁니다. 추측해서 쓰지 않습니다.

### 사실과 출처 (가장 중요)
- 모든 수치, 통계, 인용, 사건은 출처가 있어야 하며, 출처는 `## 참고 자료`에 링크로 남깁니다. 출처가 없는 수치는 쓰지 않습니다.
- 출처는 언론사, 공공기관, 리서치 기관, 기업 공식 발표를 우선합니다. 개인 블로그, 커뮤니티 글, 위키는 1차 출처로 쓰지 않습니다.
- 최근 2년 이내 자료를 우선합니다. 수치에는 기준 연도를 함께 씁니다(예: "2025년 기준 약 22조 원").
- 환율 환산, 직접 계산한 값은 본문에 '약'을 붙이고 원래 단위도 함께 씁니다(예: "34조 원(243억 달러)").
- 직접 인용은 출처 원문과 일치해야 하며, 한 글에 1~2개까지만 씁니다.
- **'국내 최대', '최초', '유일', '1위' 같은 최상급 표현**은 공인된 근거가 있을 때만 씁니다(표시광고법 리스크). 비랩트 서비스에 대해서는 쓰지 않습니다.
- 경쟁사나 타 IP를 깎아내리지 않습니다. 비교는 사실만 씁니다.
- 확인하지 못한 내용은 본문에 넣지 말고 검수 메모에 따로 적습니다.

## 6. 이미지

| 항목 | 규칙 |
|------|------|
| 커버 이미지 | 가로형. 권장 1600×900px 이상(16:9 또는 1.91:1). 커버 위에 제목이 겹쳐 보이므로, 중앙에 글자가 많은 이미지는 피합니다. SNS 미리보기 이미지로도 쓰입니다. |
| 본문 이미지 | 가로 최대 1600px |
| 형식·용량 | `.jpg`(사진) 또는 `.png`(그래픽), 장당 500KB 이하 권장 |
| 파일명 | 영문 소문자·숫자·`_`·`-`만 사용, 내용을 드러내게 짓습니다(예: `tcg_market_chart.jpg`). 기존 파일을 덮어쓰지 않습니다. |
| alt 텍스트 | `![이미지 내용을 설명하는 문장](경로)` — 빈칸으로 두지 않습니다. alt 안에 큰따옴표를 쓰지 않습니다. |
| 캡션 | 이미지 바로 다음 줄에 `*캡션*` 형식으로 1줄 |
| 권리 | 직접 촬영했거나 비랩트가 제공한 이미지, 또는 상업적 이용이 허락된 이미지만 씁니다. 출처 표기가 필요하면 캡션에 씁니다. 기사·타사 이미지는 무단으로 쓰지 않습니다. |
| AI 생성 이미지 | 캡션 끝에 `(Generated by 도구명)`을 반드시 붙입니다. 실존 작가의 화풍을 흉내 낸 이미지나 실존 인물 이미지는 만들지 않습니다. |

기존 이미지도 쓸 수 있습니다: `images/posts/`, `images/off_events/`(행사 사진), `images/occ1_title.jpg`~`occ4_title.png`(OCC 시즌 이미지)

## 7. 빌드와 확인 (저장소 접근 권한이 있을 때)

```bash
python3 -m venv .venv                              # 최초 1회
.venv/bin/pip install -r scripts/requirements.txt  # 최초 1회
.venv/bin/python scripts/build_insights.py
```

- 빌드는 `insights/{slug}/index.html`, `insights/index.html`을 생성하고, 홈페이지 `index.html`의 인사이트 미리보기(최신 4편)를 갱신합니다. 이 생성 파일은 직접 수정하지 않습니다.
- 빌드 로그에 `found: {slug}.md`가 나와야 합니다. 초안(`_` 시작)은 `skip (draft)`로 나옵니다.
- 로컬 서버(`python -m http.server`)로 `/insights/{slug}/`를 열어 커버, 제목, 이미지, 참고 자료 스타일을 확인합니다.
- **커밋과 push는 하지 않습니다.** 공개는 사람이 검수한 뒤 합니다.
- 게시글은 한국어로만 작성합니다. 홈페이지는 영어·일본어를 지원하지만 인사이트 글은 번역하지 않습니다.

## 8. 제출 전 체크리스트

검수 메모에 아래 항목을 모두 체크해서 제출합니다.

- [ ] 파일명이 영문 소문자 kebab-case이고 기존 slug와 겹치지 않는다
- [ ] 프론트매터 6개 필드가 모두 있고, `title`과 `description`이 큰따옴표로 감싸져 있으며 그 안에 `"`가 없다
- [ ] `title` 25~45자, `description` 80~150자, 태그 3~5개(중요한 태그가 앞)
- [ ] `date`가 `YYYY-MM-DD` 형식의 공개 예정일이다
- [ ] 본문에 `#`(H1)이 없고, `##` 소제목이 4~6개다
- [ ] 본문 분량이 공백 제외 1,800~2,500자다
- [ ] 모든 수치·인용이 `## 참고 자료`의 출처와 연결된다(출처 3개 이상)
- [ ] 비랩트 서비스 설명이 5장 범위를 벗어나지 않고, 최상급 표현이 없다
- [ ] 모든 이미지 파일이 실제로 존재하고, alt와 캡션이 있으며, 권리를 확인했다. AI 생성 이미지에는 표기를 했다
- [ ] (빌드 가능 시) 빌드가 오류 없이 끝났고, 로컬에서 게시글 페이지를 확인했다
